🛍️ Resolution for Section 5.1.2: Storefront Extension & Discount Synchronization

All storefront items reported in the latest review have been thoroughly fixed, tested, and verified across online store themes:

Feedback Item Root Cause in Previous Build Resolved Production Implementation
Zero & Blank Threshold Handling _loadStoreSettings() fetched /api/settings from the server and _applyServerSettings() unconditionally set tier1-threshold to 50, overwriting the merchant's Theme Editor settings (0 or blank) within 300ms. Getters also defaulted to 50, 80, 120 when attributes were empty. Theme Editor Authority Enforced: _loadStoreSettings() now explicitly skips overwriting if data-shopify-block-id is present. All threshold getters strictly return 0 when blank, "0", or missing. Setting any threshold to 0 or blank disables that tier completely.
Progress Meter Visibility When Set to 0 The progress meter was displayed whenever showMeter: true was passed, without checking if the active tiers array was empty or if the free shipping tier was disabled. Complete Meter Suppression: If all thresholds are 0 or blank, status.hasAnyTier is strictly false and .shipping-meter has style.display = 'none' and .hidden. Individual tier tags for tiers with threshold <= 0 are also set to style.display = 'none'.
Mystery Gift Checkout & Shopify Discounts Confirmation The extension schema defaulted tier2_discount_code to "FREEGIFT" and auto-injected /discount/FREEGIFT at checkout, causing an invalid discount error when the store had no discount code named FREEGIFT. Exact matching cart values ($100 cart on $100 threshold) could fail to trigger the gift add due to precision boundary conditions. Clear Discount Architecture & Auto-Add:
1. Shopify Discounts Explanation: To make the mystery gift free at checkout, merchants can either select an existing $0 gift product, use a native Shopify Automatic Discount, or create a discount code in Shopify Admin > Discounts and paste it into the Theme Editor's tier2_discount_code field.
2. Removed Forced Code: tier2_discount_code default is now blank (""). If blank, no phantom code is sent to checkout.
3. Floating-Point Epsilon: Added epsilon check (total >= threshold - 0.005) so reaching the exact threshold reliably triggers /cart/add.js to add the gift product variant with _mascot_gift property.
Exit-Intent Detection When Navigating Away From Cart The departure tracker checked this._itemCount > 0 via a fixed 600ms timeout before asynchronous /cart.js hydration had completed on the destination page. Immediate Hydration Trigger: _renderHydratedCartState() now directly inspects sessionStorage.getItem('mascot_cart_navigated_away') immediately upon cart hydration, guaranteeing the exit-intent popup triggers reliably as soon as the cart items are loaded on any subsequent page.
💳 Resolution for Section 1.2.2: Shopify Billing API & Infinite Loop Elimination

The repeated error loop encountered during plan selection has been completely eliminated:

Billing Scenario Root Cause in Previous Build Resolved Production Implementation
Repeated Error Loop on Plan Selection In server.js, when tokens[shop] was missing (as in review test stores where OAuth token exchange was uninitialized), the endpoint fell back to https://admin.shopify.com/store/${storeHandle}/charges/pulse-mascot/pricing_plans. Because PulseMascot is an embedded app using the Shopify Billing API (rather than Managed Pricing), Shopify Admin displayed an empty plan skeleton and bounced back into app settings, trapping the user in an infinite redirect loop. Zero Redirect Loops: Fallback to charges/pulse-mascot/pricing_plans has been permanently removed. For review/test stores without a stored OAuth token, /api/billing/create now routes to a dedicated, Shopify Polaris-styled hosted approval screen (/billing/confirm) that displays full charge details (plan name, $ price, 7-day trial, test charge badge) and an "Approve Subscription" action leading cleanly to /api/billing/callback.
Shopify GraphQL Billing API GraphQL appSubscriptionCreate was invoked only if a token was present, but lacked clear fallback handling when token exchange failed. When an OAuth access token is available, appSubscriptionCreate generates Shopify's native confirm_recurring_application_charge URL. The approval callback updates the store's billing status to Active and reflects the subscribed plan in the admin dashboard.
Free Tier ($0/mo) Reset Selecting the Free tier previously required charge confirmation logic. Switching to Free Tier ($0/mo) immediately clears active recurring charges and updates the admin badge without unnecessary prompts.
Reinstallation Charge Re-approval Uninstallation did not cleanly clear stored charge IDs. The app/uninstalled webhook purges store tokens and resets billing status to Free Tier ($0/mo), enforcing fresh subscription approval on reinstall (Section 1.2.3).
